Nordic nRF

Introduction

Les puces nRF sont une famille de microcontrôleurs sans fil développés par Nordic Semiconductor, très populaires dans l’IoT (Internet des objets), les objets connectés, les capteurs, les claviers et souris sans fil, les wearables et même certains produits industriels.

Elles sont très appréciées car elles combinent un microcontrôleur ARM Cortex-M, une ou plusieurs radios sans fil, une faible consommation d’énergie et de nombreuses interfaces périphériques (SPI, I2C, UART, PWM, ADC, etc.).

Dans les explications ci-dessous, le microcontrôleur ANNA-B112 est utilisé. En effet, ce module intègre une puce nRF52832 ainsi que tous les composants nécessaires à son fonctionnement, ce qui permet de disposer d’une solution prête à être intégrée dans une application. L’ANNA-B112 regroupe ainsi, dans un seul boîtier, la puce nRF, l’antenne RF, les oscillateurs, les composants passifs et, surtout, les certifications nécessaires. Cela évite de devoir concevoir et certifier soi-même la partie radio lors d’une éventuelle commercialisation du produit.

Faire clignoter une LED

Pour savoir quelle GPIO du ANNA-B112 utiliser pour la LED, on retrouve dans la datasheet l’information suivante :

On peut donc observer que la LED est branchée sur les IO_29, IO_30 et IO_31.

On peut alors écrire le code suivant dans le fichier main.c afin de faire clignoter la LED de la carte.

Attention : dans le code, on travaille avec l’appellation “nRF52 port”, qui correspond au numéro de sortie de la puce nRF à l’intérieur du boîtier. Le numéro GPIO correspond au numéro de sortie du boîtier nommé par ublox, qui n’est pas le même que celui du nRF.

Donc, comme vu plus haut, je veux faire clignoter la LED bleue, qui est la GPIO 31. Je dois alors renseigner le numéro 26 dans le code, comme indiqué dans la datasheet ci-dessous.

Le code main ci-dessous fait clignoter la LED bleue toutes les secondes.

main.c C 

#include <stdio.h>
#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>

/* GPIO pin number for the LED */
#define GPIO_PIN 26

/* Récupère le contrôleur GPIO gpio0 de ma carte
* et stocke sa référence dans la variable gpio0
*/
static const struct device *gpio0 =
    DEVICE_DT_GET(DT_NODELABEL(gpio0));

int main(void)
{
    if (!device_is_ready(gpio0)) {
        return 0;
    }

    if (gpio_pin_configure(gpio0, GPIO_PIN, GPIO_OUTPUT_INACTIVE) < 0) {
        return 0;
    }

    while (1) {
        gpio_pin_toggle(gpio0, GPIO_PIN);
        k_msleep(1000);
    }

    return 0;
}

Il est nécéssaire de configurer le projet pour utiliser les GPIOs. Pour cela, il faut ajouter la ligne suivante dans le fichier prj.conf :

prj.conf Conf 

// To use the GPIOs
CONFIG_GPIO=y

Bluetooth Low Energy

Résumé du Bluetooth Low Energy (BLE)

Le Bluetooth Low Energy (BLE) est une technologie de communication radio sans fil conçue pour permettre l’échange de petites quantités de données tout en consommant très peu d’énergie. Contrairement au Bluetooth classique, qui est optimisé pour des flux continus de données (audio, par exemple), le BLE est destiné aux appareils fonctionnant sur batterie pendant plusieurs mois ou plusieurs années, comme les capteurs, balances connectées, montres ou dispositifs médicaux.

Le fonctionnement du BLE repose sur deux mécanismes principaux :

  • l’advertising (publicité) ;
  • les connexions et les échanges de données via le protocole GATT.

Advertising

L’advertising correspond à l’émission périodique de paquets de données BLE appelés advertising packets.

Un appareil BLE qui diffuse ces paquets est appelé un advertiser.

Ces paquets permettent :

  • d’annoncer la présence d’un appareil à proximité ;
  • de transmettre certaines informations ;
  • d’indiquer si une connexion est autorisée ou non.

Les appareils situés à proximité effectuent un scan afin de détecter et de recevoir ces paquets.

L’un des principaux avantages de l’advertising est qu’il permet de transmettre des informations sans nécessairement établir une connexion BLE.

Exemple

Une balance connectée peut diffuser périodiquement son poids dans ses données d’advertising. Un smartphone ou une passerelle BLE peut alors récupérer cette information simplement en effectuant un scan.

Le smartphone lit les données reçues puis attend le prochain paquet d’advertising pour obtenir une nouvelle mesure.

Advertising connectable et non connectable

Il existe plusieurs types d’advertising selon que l’appareil autorise ou non l’établissement d’une connexion BLE.

Advertising connectable

Dans ce mode, l’appareil diffuse des paquets d’advertising et accepte les demandes de connexion provenant d’un appareil central, comme un smartphone.

Ce mode est généralement utilisé lorsqu’un échange de données via des services GATT est nécessaire.

Exemple : une montre connectée ou un capteur dont les mesures sont lues via une connexion BLE.

Advertising non connectable

Dans ce mode, l’appareil diffuse uniquement ses données d’advertising et refuse toute tentative de connexion.

Les informations doivent donc être directement incluses dans le paquet d’advertising.

Exemples :

  • balise Beacon ;
  • capteur de température transmettant périodiquement une mesure ;
  • balance diffusant uniquement son poids.

L’absence de connexion réduit le temps d’activation de la radio Bluetooth, ce qui permet généralement de diminuer la consommation d’énergie et d’augmenter l’autonomie du système.

Connexion BLE

Lorsque davantage de données doivent être échangées, un appareil peut établir une connexion.

On distingue alors :

  • le Peripheral (balance, capteur, etc.) ;
  • le Central (smartphone, ordinateur, passerelle, etc.).

La séquence devient :

Advertising → Connexion → Échange de données → Déconnexion

Une fois la connexion établie, les données ne transitent plus par les paquets d’advertising mais via le protocole GATT.

Le protocole GATT

GATT (Generic Attribute Profile) est la couche du BLE qui définit comment les données sont organisées et échangées après l’établissement d’une connexion.

GATT repose sur une structure hiérarchique :

  • Service
    • Characteristic 1
    • Characteristic 2
    • Characteristic 3

Les services

Un service regroupe des fonctionnalités similaires.

Quelques exemples :

  • Battery Service ;
  • Heart Rate Service ;
  • Device Information Service.

On peut également créer des services personnalisés.

Dans le cas d’une balance :

Weight Service

Les caractéristiques (Characteristics)

Les caractéristiques contiennent les données.

  • Weight Service
    • Weight Characteristic
    • Battery Characteristic

Une caractéristique peut :

  • être lue (Read) ;
  • être écrite (Write) ;
  • notifier automatiquement une nouvelle valeur (Notify).

Exemple de communication GATT

  1. La balance fait de l’advertising.
  2. Le smartphone la détecte.
  3. Le smartphone se connecte.
  4. Le smartphone découvre les services GATT.
  5. Il lit la caractéristique contenant le poids.
  6. La connexion est fermée.

Pourquoi ne pas utiliser GATT peut économiser de l’énergie ?

Dans une application où il faut simplement envoyer une valeur de poids puis retourner en veille, le protocole GATT apporte peu d’avantages.

Pour utiliser GATT, il faut :

  1. diffuser de l’advertising ;
  2. attendre une connexion ;
  3. établir la connexion ;
  4. découvrir les services ;
  5. échanger les données ;
  6. maintenir les événements de connexion ;
  7. se déconnecter.

Toutes ces opérations nécessitent l’activation de la radio pendant une durée plus importante quiconsomme de l’énergie.

Dans le cas d’un capteur de pesée alimenté par batterie qui doit simplement transmettre une valeur puis retourner en veille, l’utilisation d’un advertising non connectable est généralement la solution la plus économe en énergie. Le smartphone ou le récepteur n’a qu’à scanner périodiquement les paquets BLE pour récupérer le poids. Il n’est alors plus nécessaire de gérer une connexion, des services GATT ou des caractéristiques, ce qui réduit considérablement le temps pendant lequel la radio BLE reste active et augmente l’autonomie du système.

Code pour de l'advertising non connectable

Ce code utilise alors le BLE en mode advertising non connectable pour diffuser le poids mesuré à tous les appareils en mode serveur BLE en écoute à proximité.
main.c C 

/* Bibliothèques Zephyr */
#include <zephyr/kernel.h>
#include <zephyr/sys/printk.h>

/* Bibliothèques Bluetooth */
#include <zephyr/bluetooth/bluetooth.h>
#include <zephyr/bluetooth/hci.h>

/* Structure envoyée dans l'advertising */
struct adv_weight {
	uint16_t company_id;
	uint16_t weight;
} __packed;

/* Données initiales */
static struct adv_weight adv_weight_data = {
	.company_id = 0xFFAA,
	.weight = 0x6769
};

/* Callback appelée après l'initialisation Bluetooth */
static void bt_ready(int err)
{
	/* Vérification de l'initialisation */
	if (err) {
		printk("Bluetooth init failed (err %d)\n", err);
		return;
	}

	printk("Bluetooth initialized\n");
}

int main(void)
{
	int err;

	/* Poids mesuré en kg */
	double weight = 2.13;

	/* Conversion en entier (2 décimales) */
	adv_weight_data.weight = (uint16_t)(weight * 100);

	printk("Weight = %.2f kg\n", weight);

	/* Démarrage de la pile Bluetooth */
	err = bt_enable(bt_ready);

	/* Vérification du démarrage */
	if (err) {
		printk("Bluetooth init failed (err %d)\n", err);
		return 0;
	}

	/* Attente de stabilisation */
	k_sleep(K_MSEC(500));

	/* Données à diffuser */
	struct bt_data ad[] = {

		/* Flags BLE */
		BT_DATA_BYTES(
			BT_DATA_FLAGS,
			BT_LE_AD_GENERAL |
			BT_LE_AD_NO_BREDR
		),

		/* Données constructeur */
		BT_DATA(
			BT_DATA_MANUFACTURER_DATA,
			&adv_weight_data,
			sizeof(adv_weight_data)
		),
	};

	/* Démarrage de l'advertising non connectable */
	err = bt_le_adv_start(
		BT_LE_ADV_NCONN,
		ad,
		ARRAY_SIZE(ad),
		NULL,
		0
	);

	/* Vérification du démarrage */
	if (err) {
		printk("Advertising failed (err %d)\n", err);
		return 0;
	}

	printk("Advertising started\n");

	/* Diffusion pendant 5 secondes */
	k_sleep(K_SECONDS(5));

	/* Arrêt de l'advertising */
	bt_le_adv_stop();

	printk("Advertising stopped\n");

	/* Attente infinie */
	while (1) {
		k_sleep(K_FOREVER);
	}

	return 0;
}

Code pour le BLE avec le protocole GATT

Ce code utilise alors le BLE avec le protocole GATT et le UUID du service Weight Scale standard.
main.c C 

/* Bibliothèques Zephyr */
#include <zephyr/kernel.h>
#include <zephyr/sys/printk.h>

/* Bibliothèques Bluetooth */
#include <zephyr/bluetooth/bluetooth.h>
#include <zephyr/bluetooth/gatt.h>
#include <zephyr/bluetooth/uuid.h>
#include <zephyr/bluetooth/conn.h>

/* UUID du service Weight Scale standard */
#define BT_UUID_WEIGHT_SCALE_SERVICE \
	BT_UUID_DECLARE_16(0x181D)

/* UUID de la caractéristique Weight Measurement */
#define BT_UUID_WEIGHT_SCALE_MEASUREMENT \
	BT_UUID_DECLARE_16(0x2A9D)

/* Structure contenant une mesure de poids */
struct weight_measurement {
	uint8_t flags;
	uint16_t weight;
} __packed;

/* Valeur initiale de la mesure */
static struct weight_measurement weight_meas = {
	.flags = 0x00,
	.weight = 0x00
};

/* Fonction appelée lors d'une lecture GATT */
static ssize_t read_weight(
	struct bt_conn *conn,
	const struct bt_gatt_attr *attr,
	void *buf,
	uint16_t len,
	uint16_t offset)
{
	/* Récupération de la mesure stockée */
	const struct weight_measurement *value =
		attr->user_data;

	/* Copie de la mesure vers le client BLE */
	return bt_gatt_attr_read(
		conn,
		attr,
		buf,
		len,
		offset,
		value,
		sizeof(*value)
	);
}

/* Déclaration du service GATT Weight Scale */
BT_GATT_SERVICE_DEFINE(weight_service,

	/* Service principal */
	BT_GATT_PRIMARY_SERVICE(
		BT_UUID_WEIGHT_SCALE_SERVICE
	),

	/* Caractéristique contenant le poids */
	BT_GATT_CHARACTERISTIC(
		BT_UUID_WEIGHT_SCALE_MEASUREMENT,
		BT_GATT_CHRC_READ |
		BT_GATT_CHRC_NOTIFY,
		BT_GATT_PERM_READ,
		read_weight,
		NULL,
		&weight_meas
	),

	/* Autorise l'activation des notifications */
	BT_GATT_CCC(
		NULL,
		BT_GATT_PERM_READ |
		BT_GATT_PERM_WRITE
	)
);

/* Appelée lorsqu'un appareil se connecte */
static void connected(
	struct bt_conn *conn,
	uint8_t err)
{
	/* Vérification de la connexion */
	if (err) {
		printk(
			"Connection failed (err %u)\n",
			err
		);
		return;
	}

	printk("Connected\n");
}

/* Appelée lorsqu'un appareil se déconnecte */
static void disconnected(
	struct bt_conn *conn,
	uint8_t reason)
{
	printk(
		"Disconnected (reason %u)\n",
		reason
	);
}

/* Enregistrement des callbacks de connexion */
BT_CONN_CB_DEFINE(conn_callbacks) = {
	.connected = connected,
	.disconnected = disconnected,
};

/* Données d'advertising */
static const struct bt_data ad[] = {

	/* Flags BLE */
	BT_DATA_BYTES(
		BT_DATA_FLAGS,
		(BT_LE_AD_GENERAL |
		 BT_LE_AD_NO_BREDR)
	),

	/* Nom complet de l'appareil */
	BT_DATA(
		BT_DATA_NAME_COMPLETE,
		CONFIG_BT_DEVICE_NAME,
		sizeof(CONFIG_BT_DEVICE_NAME) - 1
	),
};

/* Fonction appelée après l'initialisation Bluetooth */
static void bt_ready(int err)
{
	/* Vérification de l'initialisation */
	if (err) {
		printk(
			"Bluetooth init failed "
			"(err %d)\n",
			err
		);
		return;
	}

	printk("Bluetooth initialized\n");

	/* Démarrage de l'advertising connectable */
	err = bt_le_adv_start(
		BT_LE_ADV_CONN_FAST_1,
		ad,
		ARRAY_SIZE(ad),
		NULL,
		0
	);

	/* Vérification du démarrage */
	if (err) {

		printk(
			"Advertising failed "
			"(err %d)\n",
			err
		);

		return;
	}

	printk(
		"Advertising started\n"
	);
}

/* Point d'entrée du programme */
int main(void)
{
	int err;

	/* Message de démarrage */
	printk(
		"Starting Weight Scale...\n"
	);

	/* Initialisation de la pile Bluetooth */
	err = bt_enable(bt_ready);

	/* Vérification du démarrage */
	if (err) {

		printk(
			"Bluetooth init failed "
			"(err %d)\n",
			err
		);

		return 0;
	}

	/* Poids simulé en kg */
	double weight = 2.13;

	/* Somme des poids envoyés */
	double weight_tosend = 0;

	while (1) {

		/* Ajout d'un poids à chaque cycle */
		weight_tosend = weight_tosend + weight;

		/* Conversion selon la résolution Weight Scale */
		weight_meas.weight =
			(uint16_t)(weight_tosend / 0.005);

		/* Affichage de la valeur actuelle */
		printk(
			"Weight : %d.%d kg\n",
			weight_meas.weight / 10,
			weight_meas.weight % 10
		);

		/* Envoi d'une notification aux clients connectés */
		err = bt_gatt_notify(
			NULL,
			&weight_service.attrs[2],
			&weight_meas,
			sizeof(weight_meas)
		);

		/* Vérification de l'envoi */
		if (err) {

			printk(
				"Notify failed "
				"(err %d)\n",
				err
			);

		} else {

			printk(
				"Weight sent\n"
			);
		}

		/* Attente avant la prochaine mesure */
		k_sleep(
			K_SECONDS(2)
		);
	}

	return 0;
}
